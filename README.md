# vobs

AI-first frontend framework: fine-grained signal reactivity, run-once components, compile-time diagnostics.

> Published on npm under the `@vobs/*` scope — 37 packages, unified versioning.
>
> **For AI readers**: this README is the entry point, not the full contract. Run `vobs agent-doc`
> in your project to generate an AGENTS.md (tightly pinned to the framework version), and add
> `--llms <dir>` to also emit the llms.txt / vobs-context.md / diagnostics.md knowledge-distribution
> files. Before writing code, read the **Forbidden** section below — those anti-patterns are
> intercepted by compile-time diagnostics.

## Why AI-friendly

- **Run-once components** — a component function body executes exactly once, with no re-render. The dynamic parts are signals and effects; an `Owner` tree tracks every instance and automatically releases signals, effects, and listeners on unmount.
- **Compile-time diagnostics** — C104–C234 intercept the classic React-habit migration mistakes (props snapshots, JSX stored in variables, frozen conditional returns, effect self-subscription…), and `vobs check` lists everything across the repo in one pass.
- **Contract distributed with the version** — the AGENTS.md generated by `vobs agent-doc` is pinned to the framework version, so AI does not have to rely on framework knowledge from training data that may be stale.
- **Five constraint layers** — docs → types → static analysis → compiler diagnostics → runtime guardrails (judged inside the dev browser against the real dependency set, more precise than static analysis).

## Minimal example

```bash
npm install @vobs/vobs @vobs/vite-plugin
```

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { vobsPlugin } from '@vobs/vite-plugin'

export default defineConfig({
  plugins: [vobsPlugin()]
})
```

```tsx
// counter.tsx
import { state } from '@vobs/vobs'

export function Counter() {
  const count = state(0)
  return <button onClick={() => count.value++}>Count: {count.value}</button>
}
```

```ts
// main.ts
import { createVobs } from '@vobs/vobs'
import { Counter } from './counter'

const app = createVobs({ render: () => <Counter /> })
app.mount(document.getElementById('app')!)
```

**How this differs from React**: the component body executes only once. `{count.value}` is not "text evaluated once";
it is an independent text binding generated by the compiler — on click, only that text node updates, and the
`Counter` function never re-runs. JSX is compiled at build time into targeted DOM operations (text and attributes
each become their own effects; lists go through keyed reconciliation), and the initial render is a straight line
of code with no virtual-DOM diff. All constraints that follow are covered in the next section.

## Forbidden / common anti-patterns

Typical mistakes made by porting React habits straight onto vobs. Each one has a matching compile-time diagnostic code (`vobs explain <code>` for details and the fix):

| Don't write | Why | Write instead | Code |
| --- | --- | --- | --- |
| Top-level `return cond.value ? <A/> : <B/>` in a component body | Frozen at mount; never switches afterwards | Put the ternary in a JSX child position; use `<Show when={…}>` to stay mounted while toggling visibility; use `<RouterView/>` for route branches | C104 / C107 |
| `const v = sig.value` in a component body, then handed to JSX / callbacks | A snapshot taken at creation time; it never updates when the signal changes | Read `sig.value` directly in JSX; re-read inside callbacks when they fire; pass dynamic props as getters | C118 |
| `const node = <Comp/>` stored in a variable for later use | `<Comp/>` is an immediately executed call, not a descriptive object as in React | Write the node directly at its JSX position | C108 |
| `effect(() => { sig.value++ })` | Read + write of the same signal = self-subscription loop | Declare dependencies with `effect(on([deps], fn))`; derive values with `memo` | C210 |
| `effect(() => { void load() })` calling an async function | Code before the first `await` runs synchronously, and signals it reads count toward the effect's dependencies | Fetch asynchronously with `@vobs/resource` | C106 |
| `list.value.push(x)` / `sort()` / `splice()` | The reference never changes, the signal never notifies, the UI stays on stale data | `list.value = [...list.value, x]` | C233 |
| `{cond.value ? items.map(…) : null}` | The list hides inside a ternary branch, losing keyed reuse | Make `map` a direct child expression; move the condition into each item | C232 |

All of the above can be caught ahead of time by **`pnpm check:source`** (= `vobs check`: static analysis + compiler diagnostics, everything listed in one repo-wide pass);
in dev mode the runtime guardrails (`@vobs/vobs/dev`) catch another layer in the browser console — C210/C211 are judged against the **real dependency set**, more precise than static analysis.

## DSH plugins

vobs can also be used to build DeepSeek Harness client plugins (one toolchain + four plugin packages, not published to npm, distributed via Git subdirectories): **Vobs Console** (multi-session cockpit), **Vobs DevKit** (project checks and AI guardrails), and **Vobs Studio** (AI-built vobs+Tailwind pages: design contract + MCP tools + live preview panel).
For installation, building, verification, and known pitfalls see **[docs/dsh.md](docs/dsh.md)**.

## Development

```bash
pnpm install
pnpm test        # vitest in watch mode
pnpm test:run    # single pass
pnpm typecheck   # tsc --noEmit
pnpm check:source # = vobs check: static analysis + compiler diagnostics (effect self-subscription / lists written into branches / signal reads in component bodies)
pnpm check:runtime # run the runtime guardrails route by route in a real Chrome (requires Chrome)
pnpm dev         # playground
pnpm build       # package artifacts + typecheck + playground production build
pnpm verify:packages # all publishable tarball ESM/CJS/types/source smoke checks
```

- Node 24+ (`engines` enforces >= 24.22.1), pnpm workspace
- `packages/*` — framework packages; all 37 public packages publish `dist` ESM/CJS/types and retain `src` through an explicit `/source` entry
- `playground/*` — integration examples covering router, devtools, i18n, theme, and more
